# 原生飞书批注同步

本插件直接复用原插件的 PersonalAgent 注册、设备授权、令牌刷新和飞书客户端。
运行时只需 Zotero 与本插件。已移除 lark-cli、Python、localhost HTTP 和桥接配置。

## 连接与使用

1. 安装候选 XPI，打开 Zotero 设置 → zotero-feishu-note → 连接飞书。
2. 按原插件浏览器流程完成应用注册／授权。已有连接缺权限时点击“补充授权”。
3. 点击“检测连接和权限”。此按钮验证账号与令牌 scope；文档访问权限在同步时验证。
4. 新导入文献使用 `zotero-feishu-mapping/v3` 的“飞书文档映射”子笔记，
   按 `html_attachment_key` 精确记录逐节精读、中文全文、英文全文 HTML 与飞书文档的对应关系。
   原文 PDF／HTML 快照的默认目标仍为 `english-original`。
   旧 `v1`（Markdown 附件）映射仍可用于原文批注同步，`v2`（PDF 附件）仍按三份文档路由，无需立即迁移。
5. 在原 PDF／HTML 快照或三份阅读 HTML 保存高亮、下划线和批注，即自动同步。
   阅读 HTML 的批注分别进入其对应文档；中文选中文字不会被翻译到英文原文再定位。
   右键“飞书同步 → 同步选中文献”也可手动执行。

只有映射文献走原文批注路径。错误映射直接报错，不回退到原文档导出。
无映射的普通文献仍保留原插件导出功能，其覆盖／删除语义与原版相同。
映射文献通过删除菜单删除飞书文档的操作受保护。

最终 Markdown 归档保持不变，阅读 HTML 由 Pandoc 从归档生成，保留图片、公式和可选择正文。
更改已批注 HTML 的内容会影响选区定位，导入流程禁止静默覆盖或迁移已有批注的阅读附件。
插件不负责生成 HTML；运行时仍只需 Zotero 和插件。

## 设置

| 设置               | 默认             | 范围／含义                                           |
| ------------------ | ---------------- | ---------------------------------------------------- |
| 启用原文批注同步   | 开启             | 总开关；关闭后停止自动、定期和手动批注同步           |
| 同步删除的原文批注 | 开启             | 云端确认后删除无后续回复的评论；已有回复则保留并解决 |
| 批注同步方式       | 自动             | 自动／仅手动；各机器可同时自动同步                   |
| 同步范围           | 全部有映射的文献 | 可选指定分类，包含子分类                             |
| 保存后等待         | 1.5 秒           | 0.5–300 秒，连续修改合并执行                         |
| 自动重试           | 开启             | 待处理任务持久化，重启后继续                         |
| 首次重试等待       | 60 秒            | 30–3600 秒，失败后退避，最长一小时                   |
| 多机核对间隔       | 300 秒           | 60–3600 秒；同步发生变更后先在约 30 秒复核           |
| 宽松匹配           | 开启             | 精确匹配失败后容许唯一的空白、标点、数字引用差异     |
| 同步纯高亮         | 开启             | 没有文字评论时用“Zotero 高亮”                        |
| 预览               | 手动             | 只读飞书并记录本地预览结果，不写入飞书               |
| 立即重试           | 手动             | 对待处理任务重新同步，仍执行冲突保护                 |
| 同步记录           | 最近 100 次      | 含逐批注状态、失败原因、文档入口                     |

后台每 30 秒检查到期任务，所以重试和核对的实际开始时间有调度偏差。
“刷新记录”只读本机记录，不发起飞书同步。总开关关闭后停止后续写入；
已经发出的网络请求可能仍会完成。分类用 Zotero key 保存，换机分类不可用时
明确提示重新选择，不扩大到全部文献。

## 授权

在原插件已有的文档／文件权限外申请：

- `docs:document.comment:read`
- `docs:document.comment:create`
- `docs:document.comment:update`
- `docs:document.comment:delete`

重复处理使用评论更新权限将重复评论标为已解决。删除无后续回复的评论使用删除权限；
已有授权缺少删除权限时点击“补充授权”。缺少删除权限不阻断原有新增／修改同步。
每台机器分别授权同一飞书账号；应用凭据和令牌存入 Zotero 的 Firefox Login Manager。
不需要填写命令行程序路径、App Secret 或启动后台服务。

## 多机规则与恢复

- 相同批注 ID 对应一个主评论；不同批注即使选中文字相同，也分别上传。
- 内容和选区未变时不写飞书；源批注变化时更新同一根回复。
- 评论只显示批注正文，末尾以不可见 Unicode 编码保存来源、`zfs` 内容校验值
  和重复关联。新机器读取此编码恢复关联，不依赖 Syncthing、共享索引、上一台机器
  的内部 libraryID 或本地评论 ID 文件；仍需同一 Zotero 批注 ID 与同一映射目标文档。
  编码属于文本，并非飞书原生隐藏字段，复制评论可能携带。手动编辑或导出清除编码
  后，本机已有记录会保留待处理；全新机器无法识别来源，可能另建评论。
  旧版可见后缀会在核验后原位迁移，
  保留原评论与根回复 ID。
- 两台机器同时首次上传可能短暂各建一条。各机器按相同顺序选最小评论 ID，
  将确认来源、位置与正文有效且没有后续回复的重复评论标为已解决，保留历史。
  重复根回复来源链接加 `duplicate=<主评论ID>`；中断后可继续完成。
- 已有后续回复、手动改过正文或位置异常的重复评论保留待处理，不自动解决讨论。
- 变更后的短期复核与周期核对负责发现较晚可见的重复，最终回到同一主评论。
  此方案没有服务端事务锁，不保证任何时刻都绝无短暂重复。
- Zotero 文库、批注、映射子笔记和附件本身需要通过 Zotero 支持的同步方式保持一致。
  这里处理的是批注到飞书的同步，不提供 Zotero SQLite 文件并发同步。
- 如果两台机器同时编辑同一批注的不同版本，仍需先解决 Zotero 自身的数据冲突。

本机检查点、待处理、周期计划和历史：
`<Zotero profile>/zotero-feishu-note/annotations.json`。
创建前先保存检查点；丢失创建响应时先找回远端来源标记，找不到则保持待恢复，
不盲目再次创建。损坏的本地状态文件会阻止写入，不会自动清空后重新上传。

旧版无校验片段的来源标记在评论正文与当前源批注一致时可原位升级。
如果旧评论内容已不同且没有本机记录，先保留冲突，避免覆盖飞书手工修改。

## 匹配与内容保护

目标由固定 JSON 字段确定，执行前重新核验子笔记和附件。
必须唯一定位到单个正文块内的文字，可以是一句话或半句话；不扩大为整段。
用最新文档 revision 写入 `text_element_style.comment_ids`，再回读选区与逐字符样式。
不新增／重建正文块，保留正文、公式、图片、样式和其他评论。

不支持跨块选区、公式内部或内联对象内部的选区。匹配不明确、正文发生并发变化、
远端评论被独立编辑时保留待处理。只处理文字高亮／下划线；图片、手绘和无选中文字
的便签不会自动定位。不将飞书编辑导回 Zotero。

飞书评论列表的 quote 摘要可能仍显示段落；实际选区由原生块的 comment_ids 核验。
生产读写是否已通过原生授权验证，以 [验证报告](../verification/REPORT.md) 为准。

## 构建与测试

    npm run lint:check
    npm run build
    ZOTERO_PLUGIN_ZOTERO_BIN_PATH=/path/to/zotero \
      ZOTERO_PLUGIN_KILL_COMMAND=true \
      xvfb-run -a npm test -- --no-watch --exit-on-finish

测试使用独立 Zotero profile。最后一个环境变量防止 scaffold 退出时关闭用户的 Zotero。
更新区域位于 Sync location 上方，支持检查更新、安装更新和自动更新。更新源仅指向
Zhangkuns/zotero-feishu-note 的 updates 发布清单；用户无需 GitHub 登录。
首次改用新 ID 时需停用／卸载旧插件，手动安装新 XPI 并连接飞书，后续可自动更新。

## 删除同步（beta.3）

默认开启“同步删除的原文批注”，受原文批注总开关、自动／仅手动模式和分类范围约束。
仅在 Zotero 官方云端删除日志包含该批注 key、并复核云端不存在同 key 条目后处理。
本机缺少条目、尚未下载、附件文件缺失、映射被移除，均不能单独证明删除。
因此删除要先完成 Zotero 数据同步；纯离线或尚未提交云端时保留评论等待确认。
Zotero 删除日志不可用或已裁剪、网络失败、来源标记或飞书正文被独立改动时保留待处理。

- 没有后续回复：使用官方“删除回复”接口，只删除插件创建的根回复。
- 已有后续回复：保留根回复和所有讨论，写入不可见删除标记并标记已解决。
- 写入前再次读取讨论和删除证据；新回复到达时保留讨论，不遍历删除他人回复。
  飞书接口不提供条件删除事务，极短并发窗口内新增的回复仍会保留，并在可见时解决讨论。
- 新机器可以从远端来源标记恢复历史已删除批注的评论，不依赖旧机器的 annotations.json。
- 旧机器仍保留批注时，云端删除证据会阻止其再次创建／更新。所有参与机器均须升级，
  旧 beta.2 客户端没有此规则；本地批注修改冲突仍由 Zotero 官方同步处理。
- 删除请求响应丢失时下轮回读确认；评论已不存在视为完成，不重新创建。
- 撤销删除／恢复条目后，当前云端存在条目优先于旧删除日志；恢复保留的讨论，
  或为已删除且没有后续回复的评论重新创建。飞书手动编辑或移除来源标记仍受冲突保护。
- 删除整篇文献、原文附件或映射笔记不会批量删除飞书文档／评论。

<https://open.feishu.cn/document/server-docs/docs/CommentAPI/delete.md>
